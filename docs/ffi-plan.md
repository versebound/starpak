# starpak-ffi plan

Status: not started. This note records the intended shape of the C ABI crate so the core library keeps fitting it.

## Crate

`crates/starpak-ffi`, `crate-type = ["cdylib", "staticlib"]`, header generated by `cbindgen` into `include/starpak.h`. No Rust type with a lifetime or generic crosses the boundary; everything is an opaque pointer, an integer id, a caller-provided buffer or a UTF-8 byte range.

## Handles

- `starpak_archive*` wraps `Archive` (already an `Arc` inside, `Send + Sync`). `starpak_archive_open(path, options, out)` / `starpak_archive_close(handle)`. Clones of the handle are cheap, so a process can open once and hand copies to worker threads.
- `starpak_dataforge*` wraps `DataForge`. Loaded from an archive handle or from a file.
- `starpak_reader*` wraps `EntryReader` for streaming reads (`read` into a caller buffer, returns bytes written or a negative error code; `close`).
- Entries, structs, records and enums are addressed by the dense `u32` ids the library already uses (`EntryId`, `StructId`, `RecordId`, enum index). Instances are addressed by `(struct id, instance index)`; a C-side `starpak_instance` struct holds those two integers and the library resolves them on each call, so no pointer into the mapped data is ever handed out.

## Calls

- Metadata: `starpak_entry_count`, `starpak_entry_stat(handle, id, starpak_entry_info*)` filling a POD struct (sizes, method, flags, crc, offsets, dos time) plus a separate `starpak_entry_name(handle, id, buf, cap)` that copies the name.
- Lookup: `starpak_find(handle, path)` returning the id or `-1`; `starpak_glob_begin/next/end` for iteration; `starpak_tree_*` mirrors of `DirTree`.
- Reads: `starpak_read(handle, id, buf, cap, verify)` returning the decoded size (callers size the buffer from `stat` first); `starpak_read_alloc` returning a library-owned buffer released with `starpak_free`; `starpak_open_entry` for streaming.
- CryXmlB: `starpak_cryxml_to_text(bytes, len, out_buf)` and a tree walk (`node_count`, `node_tag`, `node_attr_count`, `node_attr`, `node_child`).
- DataForge: counts, `record_by_guid`/`record_by_path`, record info (name, file, tag, guid, struct id, instance index), `struct_info`/`prop_info`, `instance_field_count`, `instance_field(name|index)` returning a tagged union `starpak_value` (kind + scalar payload, or a string range, or a pointer/reference, or an array descriptor with `first`/`count` that `starpak_array_get` indexes), and `record_to_xml`/`record_to_json` into library-owned buffers.

## Errors

Every `starpak::Error` variant maps to a stable negative error code in an enum generated by `cbindgen`; `starpak_last_error_message()` returns the thread-local message of the most recent failure. No panic crosses the boundary (`catch_unwind` at every entry point).

## Strings and memory

All strings are UTF-8 without a terminator unless the call documents a C string. Buffers returned by `_alloc` calls are freed by `starpak_free`. Callers never free handles with anything but the matching `_close`.

## Open questions

- Whether to expose the directory tree at all or let bindings build their own from the flat listing.
- Whether `starpak_value` should carry pointers into the DataForge buffer for strings (fast, lifetime tied to the handle) or copy them; the plan is pointer-plus-length tied to the handle's lifetime, documented as such.
